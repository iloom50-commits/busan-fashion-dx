## 1회차 — 2026-08-13 · 배포본 실측

### F1-01 · D6 입력 경계값 · P1 · **수정·재검증 완료**

**현상**
기업명에 `<b>굵게</b>`, 대표자에 `<img src=x onerror=1>`을 넣고 진행하니
리포트 정보표에서 **HTML로 해석**됐다. `<b>` 태그 1개, `<img>` 태그 1개가 실제로 생성됨.

**영향 화면** — 5곳 전부에서 재현
- 자가진단 결과보고서 정보표
- 진단자 자가진단 목록 카드
- 진단자 완료 진단 목록 카드
- 전문가 결과보고서 정보표
- 관리자 대시보드 표

**왜 문제인가**
악의가 없어도 터진다. 상호에 `&`나 `<`만 있어도 표시가 깨진다.
`<img onerror>`는 **관리자 대시보드를 여는 담당자 브라우저에서 실행**된다 —
기업이 입력한 값이 관리자 화면에서 도는 경로다.

**원인**
템플릿 리터럴로 HTML을 조립하면서 사용자 입력을 그대로 `${}`에 넣었다.
`innerText`로 넣는 곳(종합의견)만 안전했다.

**조치**
세 파일에 공용 `esc()` 추가 후 사용자 입력 보간 지점 **31곳**에 적용.
- `index.html` 11곳 · `expert.html` 20곳 · `admin.html` 5곳
- `test_escape.py` 신설(14건) — 5개 화면 전부를 악성 입력으로 검사

**교훈**
한 화면에서 발견해도 **같은 데이터가 나오는 모든 화면**을 세어야 한다.
기업명 하나가 5개 화면에 나온다는 것을 목록화하지 않았으면 1곳만 고쳤을 것이다.

### F1-02 · D6 입력 경계값 · P1 · **수정·재검증 완료**

**현상**
대표자에 `따옴표" onmouseover="1`을 입력하고 종업원 수 버튼을 누르니
(폼이 다시 그려지는 시점) 값이 **`따옴표`로 잘렸다.**

**왜 문제인가**
F1-01보다 실무적으로 더 위험하다. **주입 의도가 없어도** 상호나 대표자명에
큰따옴표가 들어가면 **입력값이 조용히 소실**된다.
사용자는 잘린 줄 모르고 제출하고, 잘못된 값이 보고서에 실린다.

**원인**
`value="${i.ceo||''}"` — 속성값을 큰따옴표로 감싸면서 내부 큰따옴표를 이스케이프하지 않았다.
입력값의 `"`가 속성을 조기 종료시켰다.

**조치**
F1-01과 같은 `esc()`를 `value=` 속성 전부(9곳)에 적용.
테스트에 **"폼 재렌더 후 값 보존"** 항목 추가 — 주입 여부만 보면 이 결함을 놓친다.

**교훈**
XSS 검사와 **데이터 보존 검사는 다른 항목**이다. 태그가 안 생겼다고 안전한 게 아니다.

### F1-03 · D11 권한 경계 · P2 · **설계상 수용 (조치 없음)**

**현상**
로그인하지 않고 브라우저 콘솔에서 Firestore를 직접 조회하면 진단 기록이 읽힌다.

**판정 — 결함이 아니라 명시적 결정**
`docs/superpowers/specs/2026-08-13-privacy-minimization-design.md`에서
백엔드 없이 읽기를 막을 수 없다는 구조적 제약을 확인하고,
**개인정보를 저장하지 않는 것으로 상쇄**하기로 결정했다.
노출되는 것은 기업명·사업자번호·진단점수이며 대표자·연락처·이메일은 저장하지 않는다.

**남은 위험** — 기업명·사업자번호·점수의 노출은 감수한 상태다.
읽기까지 막으려면 백엔드가 필요하며, 10개사·단기 운용 조건에서 과하다고 판단했다.
