## 1회차 — 2026-08-13 · 배포본 실측

### F1-01 · D6 입력 경계값 · P1 · **수정·재검증 완료**

**현상**
기업명에 `<b>굵게</b>`, 대표자에 `<img src=x onerror=1>`을 넣고 진행하니
리포트 정보표에서 **HTML로 해석**됐다. `<b>` 태그 1개, `<img>` 태그 1개가 실제로 생성됨.

**영향 화면** — 5곳 전부에서 재현
- 자가진단 결과보고서 정보표
- 진단자 자가진단 목록 카드
- 진단자 완료 진단 목록 카드
- 전문가 결과보고서 정보표
- 관리자 대시보드 표

**왜 문제인가**
악의가 없어도 터진다. 상호에 `&`나 `<`만 있어도 표시가 깨진다.
`<img onerror>`는 **관리자 대시보드를 여는 담당자 브라우저에서 실행**된다 —
기업이 입력한 값이 관리자 화면에서 도는 경로다.

**원인**
템플릿 리터럴로 HTML을 조립하면서 사용자 입력을 그대로 `${}`에 넣었다.
`innerText`로 넣는 곳(종합의견)만 안전했다.

**조치**
세 파일에 공용 `esc()` 추가 후 사용자 입력 보간 지점 **31곳**에 적용.
- `index.html` 11곳 · `expert.html` 20곳 · `admin.html` 5곳
- `test_escape.py` 신설(14건) — 5개 화면 전부를 악성 입력으로 검사

**교훈**
한 화면에서 발견해도 **같은 데이터가 나오는 모든 화면**을 세어야 한다.
기업명 하나가 5개 화면에 나온다는 것을 목록화하지 않았으면 1곳만 고쳤을 것이다.

### F1-02 · D6 입력 경계값 · P1 · **수정·재검증 완료**

**현상**
대표자에 `따옴표" onmouseover="1`을 입력하고 종업원 수 버튼을 누르니
(폼이 다시 그려지는 시점) 값이 **`따옴표`로 잘렸다.**

**왜 문제인가**
F1-01보다 실무적으로 더 위험하다. **주입 의도가 없어도** 상호나 대표자명에
큰따옴표가 들어가면 **입력값이 조용히 소실**된다.
사용자는 잘린 줄 모르고 제출하고, 잘못된 값이 보고서에 실린다.

**원인**
`value="${i.ceo||''}"` — 속성값을 큰따옴표로 감싸면서 내부 큰따옴표를 이스케이프하지 않았다.
입력값의 `"`가 속성을 조기 종료시켰다.

**조치**
F1-01과 같은 `esc()`를 `value=` 속성 전부(9곳)에 적용.
테스트에 **"폼 재렌더 후 값 보존"** 항목 추가 — 주입 여부만 보면 이 결함을 놓친다.

**교훈**
XSS 검사와 **데이터 보존 검사는 다른 항목**이다. 태그가 안 생겼다고 안전한 게 아니다.

**현상**

**판정 — 결함이 아니라 명시적 결정**

백엔드 없이 읽기를 막을 수 없다는 구조적 제약을 확인하고,
**개인정보를 저장하지 않는 것으로 상쇄**하기로 결정했다.
노출되는 것은 기업명·사업자번호·진단점수이며 대표자·연락처·이메일은 저장하지 않는다.

**남은 위험** — 기업명·사업자번호·점수의 노출은 감수한 상태다.
읽기까지 막으려면 백엔드가 필요하며, 10개사·단기 운용 조건에서 과하다고 판단했다.

## D12 감사 — 2026-08-13 · 설계 ↔ 구현 대조

설계 문서의 *"~한다"* 규칙 20건을 실행해 대조. **일치 15 · 불일치 3 · 미구현 2**

### F12-01 · 등급 체계 문서-구현 불일치 · P1 · **개발서 수정으로 해소**

**현상**
개발서 Ⅲ-5가 *"6개 영역 합산으로 **4개 등급**(LV2~LV5)을 자동 산정한다 · 14점 이하는 LV2 도입"*
이라 명시했으나, 구현은 **5개 등급**(LV1 6~9점 포함)이었다.
6점 진단을 실행하니 화면에 `LV1. 기초`가 표기됐다 — 문서 기준이면 `LV2. 도입`이다.

**왜 중요한가**
기업별 리포트 10부에 `LV1`이 찍히면 **발주처가 받은 개발서와 어긋난다.**
종합 분석의 등급 분포 기준도 달라진다.

**판단**
5단계 구현을 유지하고 문서를 고쳤다. 6점(전 영역 미도입)과 14점(절반 디지털화)을
같은 등급으로 묶으면 최하위 기업의 개선 시급성이 드러나지 않는다.
과업지시서 63행이 *"등급 기준은 발주기관과 협의하여 확정·변경할 수 있다"*고 허용한다.
**발주처에 변경 사실을 알려야 한다.**

**교훈**
문서에 크게 써 있을수록 "당연히 됐겠지"로 넘어간다.
**값을 바꿔 결과가 변하는지 실행**해야 잡힌다.

### F12-02 · Track B 기본 적용 미구현 · P2 · **구현 완료**

개발서 Ⅲ-1과 과업지시서 66행이 **두 문서 모두** *"봉제 제조사는 Track B 기본 적용"*이라
명시했으나 전문가 진단에는 아무 안내가 없었다. 자가진단에는 이미 권장 표시가 있었다.
→ Track B에 '기본' 배지와 안내 문구 추가. 자가진단 값이 있으면 그것이 우선.

### F12-03 · 20개사 종합 분석 보고서 미구현 · P1 · **구현 완료**

과업지시서 76·80행이 요구하는 산출물. 관리자 화면에 차트는 있었으나 보고서로 뽑을 수 없었다.
→ 7개 절 구성 보고서 발행 기능 추가. **기업 단위 집계**(건수 아님)가 핵심 설계 판단.

### F12-04 · Chart.js 기술 문구 · P3 · **개발서 수정**

개발서 Ⅴ가 *"Chart.js 기반 레이더·막대 차트"*라 기술했으나 막대는 HTML로 교체됨.
기능 문제가 아니라 문서 갱신 대상.

특히 값진 확인 두 가지 (안내문에 약속해 놓고 검증하지 않았던 것):

- **오프라인 동작** — 진단자 안내 FAQ가 *"입력과 임시저장은 인터넷 없이도 됩니다"*라고
  약속했다. **네트워크를 실제로 끊고** Track 선택 → 기본정보 → 사진 건너뛰기 → 점수 입력까지
  진행했고 임시저장도 정상이었다. 문구가 사실임을 실측했다.

  진입 가능했다. `try/catch`가 실제로 동작한다.

**성능** — 진단 100건에서 관리자 목록 199ms, 종합보고서 집계 278ms.
10개사 규모에서는 여유가 크다.
